# ob-stores Implementation Plan

> **For agentic workers:** executed inline (superpowers:executing-plans). Steps use checkbox (`- [ ]`) syntax. Spec: `docs/superpowers/specs/2026-09-25-ob-stores-design.md`.

**Goal:** A vanilla PHP 8.4 + MySQL 8.4 OB equipment store with an append-only ledger, a recursive-CTE kit planner (Vue) beside a legacy jQuery store screen, locked pack/return transactions and traceability.

**Architecture:** Front controller + hand-rolled router → controllers → repos (raw PDO SQL) / services (transactions) → PHP templates or JSON. Stock and gear status are derived from one `movements` table via two SQL views. Vue planner built by Vite into `public/build`, located via the Vite manifest.

**Tech Stack:** PHP 8.4.26, MySQL 8.4.11 (docker), Composer 2.10.3, PHPUnit 13.3.4 (dev), Vue 3.5.43, Vite 8.3.1, @vitejs/plugin-vue 6.0.9, jQuery 3.7.1, Node 24 (engines >=22).

## Global Constraints

- No PHP framework, no ORM, no runtime Composer packages. PHPUnit is the only Composer dev dependency.
- `declare(strict_types=1);` in every PHP file; typed properties and return types throughout.
- PDO: `ERRMODE_EXCEPTION`, `EMULATE_PREPARES=false`, prepared statements for all input.
- All HTML output through `e()`. CSRF token on every POST (`_csrf` field or `X-CSRF-Token` header).
- No UPDATE/DELETE on `movements`. Stock/status only via new movement rows.
- One hand-written stylesheet with CSS custom properties; no CSS framework; inline SVG only.
- No real station/network/club/venue/person names; no food domain and no ERP branding.
- Private repo `ad0maa/ob-stores`; no CI, no deploy, no public visibility.
- Commit once per phase (brief requirement), emoji prefix per CLAUDE.md (✨ feature, ♻️ refactor, 🐛 fix, 🚧 WIP). Commit body explains any new PHP 8.4 / MySQL 8 feature in 1–2 sentences.
- Keep `DECISIONS.md` current as decisions are made.
